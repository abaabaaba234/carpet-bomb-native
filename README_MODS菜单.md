# 地毯轰炸 v0.6.1

v0.6.1 修复加载和舰桥后台开销：载荷准备拆到多帧执行，准备好后舰桥停止飞机／弹体轮询，详细诊断默认关闭；字段冲突和表更换改为安全暂停、清理后重验，菜单注册失败自动续接重试。游戏版本号不再单独触发拒绝，代码和布局检查继续保留。

2026-10-17，作者确认两个更新均已测试，自己使用暂未发现问题。反馈缺少具体报错或同局日志，因此本次只是针对可能原因进行的尝试性修复，不保证完全解决所有人的舰桥卡顿、不加载或偶发失效。GitHub Release 沿用已上传 A 网的同一 ZIP，不重新打包。

[下载 v0.6.1 安装包](https://github.com/abaabaaba234/carpet-bomb-native/releases/download/v0.6.1/NativeCarpetBomb_v0.6.1.zip)

新增“信标落地额外等待（秒）”：0到60秒，步长1秒，默认0秒保留现有节奏。Esc → MODS → 原生地毯轰炸中调整并点击应用；管理器也新增0/3/5/8/10/15/20/30/60秒预设。先试5秒，需要更长撤离时间再调到8或10秒。旧配置缺少`call_delay`时跟随管理器；`call_delay=5`为额外等待5秒，`call_delay=manager`恢复部署预设。

该值增加地毯轰炸信标激活后的基础等待，仅后续调用生效；不是从落地到第一枚炸弹爆炸的精确总时长，实际还包括飞行时间及游戏修正。已经开始的倒计时不变。归零或关闭模组恢复本模组认领的原值。其他飞鹰的等待、调用冷却与装填独立。

用户于2026-10-16确认v0.5.9集束时机“现在刚好”。本版保留其按实际高度恢复0.35秒原生计时的行为、每架20枚主弹和每枚8枚原生子弹。69组离线检查通过，覆盖新增等待的六弹种写入、非零基线叠加、保存重启、管理器切换、竞争写入及失败回滚。历史版本的新增等待及菜单文字修正获用户可用反馈，v0.6.1已获作者本地实机测试正常的反馈；联机及全部预设组合仍未验证。

本版包含飞鹰集束、燃烧、毒气弹，以及相对投掷方向的“左右 / 前后”来袭选择。保留现有次数、冷却、目标前移、载荷修复和恢复逻辑。每架固定投下20枚主弹；集束主弹还会产生原生子弹。

## 安装

关闭游戏，用 Arsenal / HD2MM 导入 `NativeCarpetBomb_v0.6.1.zip` 替换旧版，启用核心并选择管理器预设，按加载器要求 Purge + Deploy 后重启。不要同时部署原版与此适配版。

需要 Bingus Shared Loader v18。游戏内 MODS 页面另外需要安装 **Bingus ModOptionsMenu API 1 / version 2**；Shared Loader 本身不提供菜单。没有菜单或菜单注册失败时，管理器预设和配置文件仍可使用。

## MODS 菜单

在 Esc → MODS → 原生地毯轰炸中设置，点击“应用”后写入配置文件，再由原有更新路径处理。第一行 `Language` 提供 `简体汉字` / `English`，只影响本模组标题、标签和选项，默认中文。无论选择哪种语言，全部设置介绍始终同时显示中文和英文；管理器中的核心与预设介绍也为中英双语。应用语言后关闭并重新打开 Esc 菜单刷新；菜单会将 English 显示为 ENGLISH。

All setting descriptions show Chinese and English together in either language mode. The Language option still controls this mod's title, labels and choices, with Chinese as the default. Manager preset descriptions are bilingual as well. Apply the language change, then close and reopen the Esc menu.

## 配置与兼容

配置仍是 `%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\CarpetBombNative.cfg`，日志仍是同目录的 `CarpetBombNative.log`。各字段的 `manager` 保留独立含义，部署时的预设仍作为回退值；菜单选择自定义后仅覆盖该参数。恢复“跟随管理器”会把对应键保存为 `manager`。

旧配置缺少 `language` 时使用中文；缺少 `direction` 时跟随管理器，默认左右，其余参数保持不变。`direction=90` 为左右，`direction=180` 为前后，`direction=manager` 跟随部署预设。菜单保存保留原配置注释和未知键，并新增 `language=zh` 或 `language=en`。有效配置优先于菜单提供者的旧缓存；外部编辑有效配置后菜单同步。未点击应用的编辑不会被相同有效配置的同步清除。

保持原版装填保存为 `rearm=-1`，无限次数保存为 `uses=-1`，关闭保存为 `enabled=0`。`bomb_count` 仍强制为 20，旧数量覆盖仍被忽略。

## v0.6.1 加载、舰桥休眠与恢复

- 必须在进任务前准备资源和补给附带字段，因此舰桥仍允许分帧准备和低频静态校验。每帧最多准备两张表；每个哈希探测步骤最多读取64个槽位，保留游标，全部验证后才发布。未就绪时不反复分配私有表。
- 准备后，场景状态最多每0.25秒轻量检查一次。舰桥停止飞鹰、弹体、集束高度与诊断采样，配置／菜单／静态检查约每5秒一次；任务内保留原调度。菜单应用走立即调度，外部改文件在下次轮询读取。退出任务清除动态跟踪，保留下一任务所需的资源和授予。
- `waiting`／`preparing` 表示等待或分帧准备；`active` 表示数据准备完成，结合 `in_mission` 判断是否正在任务；`disabled` 为明确关闭；`suspended` 表示安全暂停。配置中的 `enabled=0` 保留，不会擅自开启。
- 冲突值不覆盖。暂停后先恢复仍拥有的修改，清理前三轮至少间隔1秒，之后至少间隔30秒；失败记录继续保留。清理完成后按1到30秒退避重验。数据暂时不可读不能当作已退休；只有指针明确指向新的有效分配时才退休旧静态记录，不读写旧地址。
- 战备／弹体记录、组件表或根指针更换后重新定位与验证；仍有效的本模组别名和私有飞鹰表可以复用。已经发布或尝试发布的私有表保留到进程退出，最多保留4个分配；达到上限会安全暂停并提示重启，避免反复换表造成无界增长。外部修改仍未消失或无法确认所有权时，继续暂停。
- Loader 按 API 1 与必要方法检查，推荐使用 v18；依赖晚到时借已有 update 低频等待。update 不存在时不设置成功标记，允许之后重新执行 addon。原回调参数、返回值及异常保留。其他 MOD 直接覆盖 update 且不调用原回调、或旧版抢先加载，仍需处理部署冲突；日志会提示重复版本。
- 菜单 API 1/version 2+ 失败后退避重试，分别记住已注册控件和已绑定回调；更换提供者后重新注册。不会因重试累加回调。更换炸弹仍需重启并进入新任务，已有次数和倒计时仍可能需要新任务更新。
- `diagnostics=0` 默认关闭详细飞行／集束日志；排查时可在配置文件设为 `1`，旧的采样窗口和数量上限仍保留。生产模式继续执行必要的集束引信与高度修复。重复日志30秒去重，最多保留64条去重记录；日志写入失败不阻断原更新回调。
- 69组离线检查通过，含真实菜单 API 隔离、分帧／长探测链预算、舰桥休眠、任务切换、表更换、所有权恢复和菜单部分失败。本次未运行游戏或联机，历史用户反馈仅对应原来标注的版本。
