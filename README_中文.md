新增“信标落地额外等待（秒）”：0到60秒，步长1秒，默认0秒保留现有节奏。Esc → MODS → 原生地毯轰炸中调整并点击应用；管理器也新增0/3/5/8/10/15/20/30/60秒预设。先试5秒，需要更长撤离时间再调到8或10秒。旧配置缺少`call_delay`时跟随管理器；`call_delay=5`为额外等待5秒，`call_delay=manager`恢复部署预设。

该值增加地毯轰炸信标激活后的基础等待，仅后续调用生效；不是从落地到第一枚炸弹爆炸的精确总时长，实际还包括飞行时间及游戏修正。已经开始的倒计时不变。归零或关闭模组恢复本模组认领的原值。其他飞鹰的等待、调用冷却与装填独立。

用户于2026-10-16确认v0.5.9集束时机“现在刚好”。本版保留其按实际高度恢复0.35秒原生计时的行为、每架20枚主弹和每枚8枚原生子弹。69组离线检查通过，覆盖新增等待的六弹种写入、非零基线叠加、保存重启、管理器切换、竞争写入及失败回滚。历史版本的新增等待及菜单文字修正获用户可用反馈，v0.6.1已获作者本地实机测试正常的反馈；联机及全部预设组合仍未验证。

本版包含飞鹰集束、燃烧、毒气三种弹体及左右 / 前后来袭选择，使用方法见 [MODS 菜单说明](README_MODS菜单.md)。中文与英文模式下全部设置介绍均同时显示两种语言，标题、标签和选项仍跟随语言选择，默认中文。管理器预设介绍也为双语。安装此包应导入 `NativeCarpetBomb_v0.6.1.zip`。

进入新任务时，通过必带的“补给”附带原生 `CarpetBomb` 战备，不占四个自选槽位。输入为 **↑ → ↑ → ↑ →**。需要 **Bingus Shared Loader v18**，参考布局来自 Steam build **25480438** / EXE **1.8.46015.0**；运行时验证PE架构、映像边界、代码锚点和数据身份，不按版本号、时间戳或精确映像大小拒绝。RVA／结构变化仍须重新适配，不代表任意未来版本可用。

## 安装与设置

1. 关闭游戏，在 Arsenal / HD2MM 导入 `NativeCarpetBomb_v0.6.1.zip` 替换旧版。
2. 启用“核心”，选择次数、每次使用之间的调用冷却、飞鹰返航装填冷却、炸弹类型、来袭方向和目标前移距离。
3. 按加载器文档设置启动脚本优先级，先 Purge（清除旧部署），再 Deploy（部署当前选择），然后重启游戏，进入新任务。

默认：2 次、15 秒间隔、装填保持原版、原版飞鹰空袭炸弹、原版 1x 数量、目标前移80米、左右来袭。前移 80 米已在 200 kg 实测中改善信标两侧覆盖；500 kg 已在前移 0 米下验证正常投弹。

| 选项 | 可选值 |
| --- | --- |
| 使用次数 | 1、2、3、4、5、6、8、10、无限 |
| 调用冷却（每次使用之间） | 0、5、10、15、30、60、120、300、600、900 秒 |
| 飞鹰返航装填冷却 | 保持原版，或 0、5、10、15、30、60、120、150、180、300、600、900 秒 |
| 炸弹类型 | 原版空袭、地毯式轰炸200 kg、飞鹰500 kg、飞鹰集束、飞鹰燃烧、飞鹰毒气 |
| 飞鹰来袭方向 | 左右横穿投掷方向 / 前后沿投掷方向；默认左右 |
| 投弹数量 | 暂固定原版 1x，每架 20 枚；总数随实际飞机数变化 |
| 投弹目标前移 | 0、40、80、120、160 米 |
| 信标落地额外等待 | 0、3、5、8、10、15、20、30、60 秒；菜单支持0到60秒逐秒调整 |

装填冷却用于次数耗尽或手动重新武装时的基础装填时间。游戏中全部携带的飞鹰战备共用这个值；舰船升级仍由游戏计算。“保持原版”不修改该字段。

炸弹选项更换实际弹体与对应原生资源包，沿用其伤害、爆炸、延时和状态定义。飞鹰集束使用286号主弹，经417号爆炸每枚分出8枚131号子弹；每架仍投下20枚主弹，弹体与特效负荷可能明显增加。燃烧使用141号弹体及359号爆炸的原生火焰模板；毒气使用188号弹体及331号爆炸的原生毒气状态体积。200 kg 与空袭炸弹使用相同模型和撞击特效；500 kg 使用自己的资源包和延时爆炸资源。更换弹体后需重启并进入新任务，让资源载入。500 kg /1x/前移 0 米已实测正常投弹。

“投弹目标前移”沿飞鹰进场方向调整本战备新出动飞机的目标，用于平衡信标两侧的覆盖。0 米保留原落点。它不移动红色信标、不改变炸弹数量，已出动飞机不重复调整；其他飞鹰战备保留原样。方向选项使用独立飞鹰组件的进场角度字段：左右90度，前后180度。已出动飞机保留原设置；前移仍沿实际来袭方向计算。本模组不改写游戏代码。

## 配置与日志

位置：`%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\CarpetBombNative.log` / `CarpetBombNative.cfg`。

```ini
language=zh
enabled=1
diagnostics=0
uses=manager
cooldown=manager
rearm=manager
bomb=manager
bomb_count=manager
forward=manager
direction=manager
call_delay=manager
```

`manager` 使用部署选项。支持 `uses=1..100` 或 `-1`（无限），`cooldown=0..1800`，`rearm=-1`（原版）或 `0..1800`，`bomb=170/192/239/286/141/188`（空袭 / 200 kg / 500 kg / 集束 / 燃烧 / 毒气），`forward=0..300`米，`direction=90/180`（左右 / 前后）。缺少键时使用管理器设置。旧 `bomb_count` 数值覆盖会被忽略，实际数量始终保持 20。

保存后重新读取。次数和已在进行的计时可能需要新任务才能更新；弹体、资源包更换后应重启游戏。前移距离与来袭方向只用于新出动飞机。

## 禁用与开发

`enabled=0` 撤销默认携带与本插件拥有的战备字段，停止调整后续飞机。已有飞机保持已设置的目标；实体/组件映射留到进程退出，避免已创建实体持有失效指针。管理器禁用、Purge + Deploy 并重启后恢复原版。不会修改账户解锁或装备存档。

源码：`src/core.lua`；打包：`python tools/build.py`；离线检查：`python tests/test_runtime.py`。

## v0.6.1 加载、舰桥休眠与恢复

- 必须在进任务前准备资源和补给附带字段，因此舰桥仍允许分帧准备和低频静态校验。每帧最多准备两张表；每个哈希探测步骤最多读取64个槽位，保留游标，全部验证后才发布。未就绪时不反复分配私有表。
- 准备后，场景状态最多每0.25秒轻量检查一次。舰桥停止飞鹰、弹体、集束高度与诊断采样，配置／菜单／静态检查约每5秒一次；任务内保留原调度。菜单应用走立即调度，外部改文件在下次轮询读取。退出任务清除动态跟踪，保留下一任务所需的资源和授予。
- `waiting`／`preparing` 表示等待或分帧准备；`active` 表示数据准备完成，结合 `in_mission` 判断是否正在任务；`disabled` 为明确关闭；`suspended` 表示安全暂停。配置中的 `enabled=0` 保留，不会擅自开启。
- 冲突值不覆盖。暂停后先恢复仍拥有的修改，清理前三轮至少间隔1秒，之后至少间隔30秒；失败记录继续保留。清理完成后按1到30秒退避重验。数据暂时不可读不能当作已退休；只有指针明确指向新的有效分配时才退休旧静态记录，不读写旧地址。
- 战备／弹体记录、组件表或根指针更换后重新定位与验证；仍有效的本模组别名和私有飞鹰表可以复用。已经发布或尝试发布的私有表保留到进程退出，最多保留4个分配；达到上限会安全暂停并提示重启，避免反复换表造成无界增长。外部修改仍未消失或无法确认所有权时，继续暂停。
- Loader 按 API 1 与必要方法检查，推荐使用 v18；依赖晚到时借已有 update 低频等待。update 不存在时不设置成功标记，允许之后重新执行 addon。原回调参数、返回值及异常保留。其他 MOD 直接覆盖 update 且不调用原回调、或旧版抢先加载，仍需处理部署冲突；日志会提示重复版本。
- 菜单 API 1/version 2+ 失败后退避重试，分别记住已注册控件和已绑定回调；更换提供者后重新注册。不会因重试累加回调。更换炸弹仍需重启并进入新任务，已有次数和倒计时仍可能需要新任务更新。
- `diagnostics=0` 默认关闭详细飞行／集束日志；排查时可在配置文件设为 `1`，旧的采样窗口和数量上限仍保留。生产模式继续执行必要的集束引信与高度修复。重复日志30秒去重，最多保留64条去重记录；日志写入失败不阻断原更新回调。
- 69组离线检查通过，含真实菜单 API 隔离、分帧／长探测链预算、舰桥休眠、任务切换、表更换、所有权恢复和菜单部分失败。本次未运行游戏或联机，历史用户反馈仅对应原来标注的版本。
