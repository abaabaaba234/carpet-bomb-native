# 地毯式轰炸默认携带 v0.4.0

进入新任务时，通过必带的“补给”附带原生 `CarpetBomb` 战备（类型 103），不占四个自选槽位。输入组合为 **↑ → ↑ → ↑ →**。需要 **Bingus Shared Loader v18**，支持 Steam build **25480438** / EXE **1.8.46015.0**。

v0.1.0 的实机测试已确认默认携带成功，但投掷后崩溃。转储确认缺失载荷 `6ccb976676ef6cc6` 的 EagleComponent 查询返回空。v0.2.0 为这个载荷补上 18 处实体/组件映射，借用现有飞鹰模型、炸弹与资源包，并为地毯轰炸建立独立的 `EaglePayload_CarpetBombing`（6）记录。现有飞鹰空袭和烟雾的投弹记录保留原样。

v0.2.0 生成了炸弹，但继承普通空袭的 1000 米进场高度使地毯轰炸立即投弹，落点偏离信标约 200～350 米。v0.3.0 仅将地毯轰炸的独立记录调整为 120 米进场高度，实机已确认炸弹落在信标附近。原有飞鹰记录不受影响。

v0.3.0 的次数/冷却选项档仅 224 字节，完整部署后在游戏原生资源解析器中启动崩溃。仅改成 240 字节的字节码档仍然崩溃。v0.3.1 把选项容器补齐到至少 4096 字节，保留精确的内部资源长度，同时使用与游戏匹配的 LuaJIT 2.1 字节码。完整包已成功进入舰桥并加载所选参数。清单使用 JSON 转义字符，避免 Arsenal 导入时把中文标签显示成乱码。轰炸载荷和 120 米高度保持一致。

v0.4.0 保留上述容器修复。调用冷却明确标为“每次使用之间”；新增“飞鹰返航装填冷却”，设置次数耗尽后飞鹰返回装填、恢复使用次数时的基础冷却。它也用于手动重新武装。游戏为所有携带的飞鹰战备共用这个冷却，因此新选项会影响全部飞鹰战备，默认“保持原版”。舰船升级仍由游戏计算。

本次完整包通过管理器导入并冷启动成功。装填原版基础值读到 150 秒，经插件配置暂调 30 秒后，实机确认仅这个冷却字段改变；次数、调用间隔及其他飞鹰记录保持原样，随后恢复到 150 秒，配置文件原样恢复。验证覆盖参数与恢复过程，尚未重新计时完整的任务内返航装填周期。

原生名称、类型和输入保留。调用来源、冷却类型、资源包与飞鹰重新武装采用个人飞鹰机制。原生轰炸路径每架安排 20 枚炸弹；此前测试环境中一次调用生成 3 架飞机，共 60 枚炸弹。具体验证状态见 `VALIDATION.json`。测试覆盖当前本机游戏版本，联机同步效果尚未验证。

## 安装与设置

如果此前由本项目直接部署了 `patch_54`，先在项目目录运行 `python tools/remove_test.py`，再改用管理器部署，避免留下管理器之外的测试补丁。当前游戏中的修复保留到退出。

1. 关闭游戏，用 Arsenal / HD2MM 导入 `NativeCarpetBomb_v0.4.0.zip`，替换旧版。
2. 启用“核心”。分别选择次数、每次使用之间的调用冷却和飞鹰返航装填冷却，默认 **2 次、15 秒、装填保持原版**。
3. 确认加载器按其文档取得启动脚本优先级，Purge + Deploy 后启动游戏。
4. 进入新任务，检查额外的地毯式轰炸，再测试投弹。

次数可选 1、2、3、4、5、6、8、10、无限。

调用冷却（每次使用之间）可选 0、5、10、15、30、60、120、300、600、900 秒。

飞鹰返航装填冷却可选保持原版，或 0、5、10、15、30、60、120、150、180、300、600、900 秒。这是装填的基础冷却，不改变飞鹰飞行和投弹动作。次数和装填仍使用游戏的个人飞鹰管理。

日志与设置位于 `%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\CarpetBombNative.log` / `CarpetBombNative.cfg`：

```ini
enabled=1
uses=manager
cooldown=manager
rearm=manager
```

`manager` 使用部署选项。也可填 `uses=1` 至 `100`，或 `-1` 表示无限；`cooldown=0` 至 `1800` 表示每次使用之间的间隔；`rearm=0` 至 `1800` 表示返航装填基础冷却，`rearm=-1` 保留当前游戏设置。旧配置缺少 `rearm` 时自动使用管理器选项。保存后重新读取，已创建的任务状态或正在进行的计时可能需进入新任务才生效。从失败原型升级时，请把配置中的 `enabled=0` 改为 `1`。

## 禁用与移除

`enabled=0` 会撤销默认携带、插件修改的战备字段和自己设置的返航装填冷却。装填选择“保持原版”时不会修改这个共用字段；从自定义值改回“保持原版”会恢复插件启动时读到的值。为避免已创建实体持有失效指针，已经补上的实体/组件映射保留到当前游戏进程退出。禁用 mod、Purge + Deploy 并重启游戏后，全部恢复原版。这些修改都在当前进程内，不修改账户解锁或装备存档。

版本、组件布局或配置发生冲突时停止授予，并尝试恢复自己修改的战备字段。发生异常时不要继续调用当前任务里已经出现的实验战备，重启游戏后再排查。

源码：`src/core.lua`；打包：`python tools/build.py`；离线验证：`python tests/test_runtime.py`。
